# Tonum Wallet — Telegram Mini App

Мультивалютный кошелёк внутри Telegram: счета в ₽ рублях, $ долларах, € евро, ¥ юанях и TON, обмен валют по рыночному курсу, пополнение и вывод через [@CryptoBot (Crypto Pay API)](https://help.crypt.bot/crypto-pay-api), вход по 4-значному код-паролю, уведомления в чат.

```
web/      React 19 + Vite — Mini App (дизайн «жидкое стекло»)
server/   Node.js + Fastify + PostgreSQL — API, бот (grammY), фоновые воркеры
```

## Как работают деньги

| Операция | Поток |
|---|---|
| Пополнение | `POST /api/deposits` → счёт в Crypto Pay (для ₽ $ € ¥ — счёт **в фиатной валюте**, оплачивается USDT или TON по курсу) → подписанный вебхук `invoice_paid` → на баланс зачисляется ровно сумма счёта. Если вебхук потерялся, раз в 30 с сверка через `getInvoices` |
| Обмен | `POST /api/exchange/quote` → курс из `getExchangeRates`, комиссия 1 %, котировка **подписана и зафиксирована на 30 секунд** → `POST /api/exchange`: обе стороны обмена и комиссия проводятся одной транзакцией. Каждую котировку можно исполнить только один раз |
| Вывод | Проверка код-пароля → в одной транзакции блокируются `сумма + комиссия` → выплата в @CryptoBot (`transfer`, `spend_id` = id вывода): TON в TON, фиат в USDT по рыночному курсу за вычетом спреда → `completed`. При явном отказе провайдера всё возвращается на баланс |

**Учёт** ведётся по двойной записи: `accounts` + неизменяемый журнал `ledger_entries`. Триггер при COMMIT проверяет, что каждая транзакция сходится к нулю **по каждой валюте отдельно**: 100 ₽ не могут «уравновеситься» 100 $. Суммы хранятся целыми числами в минимальных единицах (`BIGINT`), курсы — числами с фиксированной точкой (BigInt × 10¹⁸). Float на денежном пути нигде не используется.

## Защита

- **Вход в два шага.** Сначала подпись Telegram `initData` (HMAC-SHA256, сравнение за постоянное время, проверка срока `auth_date`), затем **4-значный код-пароль** при каждом открытии. После кода сервер выдаёт подписанную сессию на 30 минут, без неё API не отдаёт ни балансы, ни операции. Сессия хранится только в памяти и сбрасывается, если свернуть приложение больше чем на 2 минуты.
- **Нельзя уйти в минус**: списание делается условным `UPDATE … WHERE balance + amount >= 0`, а в БД стоит `CHECK (balance >= 0)`. Тест запускает 8 параллельных выводов и проверяет, что прошли ровно два.
- **Идемпотентность**: заголовок `Idempotency-Key` обязателен для пополнения и вывода. Повтор с тем же ключом возвращает ту же операцию, с другими параметрами — `409`.
- **Исход вывода неизвестен** (таймаут или 5xx): средства остаются заблокированными, воркер сначала проверяет `getTransfers(spend_id)` и только потом повторяет отправку. Crypto Pay принимает каждый `spend_id` один раз, поэтому двойной выплаты не будет. После 5 неудачных попыток вывод уходит на ручную проверку (`review`) и **никогда не возвращается автоматически**.
- **Код-пароль** хранится как scrypt-хеш с солью и повторно запрашивается на каждый вывод. Простые коды вроде 1234 и 0000 отклоняются. После 5 ошибок вход блокируется на 15 минут, попытки сериализуются блокировкой строки.
- **Обмен**: котировка подписана HMAC, привязана к пользователю и живёт 30 секунд. Поменять в ней сумму или курс нельзя, использовать повторно тоже. Если курсы недоступны, сервер честно отвечает `503` и не подставляет устаревшие.
- **Вебхуки**: Crypto Pay проверяется по HMAC подписи от сырого тела, Telegram — по `X-Telegram-Bot-Api-Secret-Token`.
- **Лимиты**: минимум и максимум на операцию, суточный лимит вывода (точный, под блокировкой счёта), не больше 5 неоплаченных счетов на пользователя.
- **Ограничение частоты запросов**: 120 в минуту на пользователя, 10 в минуту на денежные операции и PIN.
- Строгий CSP и Helmet, zod-валидация входных данных, лимит размера тела, ошибки без внутренних деталей. Токены и подписи вырезаются из логов. Журнал проводок защищён от UPDATE и DELETE.
- Mock-провайдер в `NODE_ENV=production` запустить нельзя: конфиг отказывается стартовать.

## Запуск

### 1. Подготовка
1. Создайте бота у [@BotFather](https://t.me/BotFather), получите `BOT_TOKEN`. В `/mybots → Bot Settings → Configure Mini App` укажите URL приложения.
2. В [@CryptoBot](https://t.me/CryptoBot) (для тестов — [@CryptoTestnetBot](https://t.me/CryptoTestnetBot)) откройте **Crypto Pay → Create App** и получите токен. В настройках приложения:
   - **Webhooks** → `https://<ваш-домен>/api/webhooks/cryptopay`
   - включите **Transfers**: без этого вывод работать не будет
   - пополните баланс приложения — из него идут выплаты пользователям.
3. Ключи понадобятся на шаге 2. Установщик сам запишет их в `.env`.

### 2. Продакшен (сервер с Ubuntu)
Нужен VPS с Ubuntu 22.04/24.04 и 2 ГБ RAM, а также домен, A-запись которого указывает на IP сервера. Загрузите проект на сервер и запустите установщик:
```bash
sudo bash deploy/install.sh
```
Скрипт ставит Docker, спрашивает домен и ключи, сам генерирует пароли и запускает PostgreSQL, приложение и Caddy. Caddy автоматически получает HTTPS-сертификат. Миграции применяются при старте. После запуска скрипт покажет, что настроить в @BotFather и Crypto Pay.

Без скрипта: заполните `.env` по образцу `.env.example` и выполните `docker compose up -d --build`.

### Тест на своём Mac (без сервера и домена)
Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/). Запустите его, затем в папке проекта выполните:
```bash
bash deploy/mac-test.sh
```
Скрипт спросит ключи бота и Crypto Pay (testnet), запустит приложение и откроет бесплатный публичный HTTPS-туннель. Туннели перебираются по очереди, пока один не подключится: сначала Cloudflare (ему нужен порт 7844, который в России часто заблокирован), затем localhost.run и Pinggy через встроенный в macOS SSH. Адрес туннеля бот получает сам, в том числе если адрес сменится во время работы. Пока идёт тест, окно Терминала должно оставаться открытым, а Mac — не уходить в сон. Сервис туннеля видит проходящий через него трафик, поэтому такой режим подходит только для тестовых денег.

### 3. Локальная разработка
```bash
npm ci
# Postgres: docker compose up -d db  (или свой), затем в .env:
#   NODE_ENV=development  PAYMENT_PROVIDER=mock  BOT_MODE=off  PUBLIC_URL=http://localhost:3000
npm run dev:server                       # API на :3000
npm run dev:initdata -w server           # подписанный initData для браузера
echo "VITE_DEV_INIT_DATA=<вывод>" > web/.env.local
npm run dev:web                          # Mini App на :5173
```
С mock-провайдером кнопка «Открыть счёт» ведёт на тестовую страницу оплаты.

### Тесты
```bash
TEST_DATABASE_URL=postgres://postgres@localhost:5432/wallet_test npm test
```
Интеграционные тесты идут на настоящем PostgreSQL. Они покрывают гонки, идемпотентность, повторные вебхуки, возвраты, неизвестный исход вывода, блокировку PIN, лимиты, частоту запросов и инварианты журнала. Тесты, проверка типов и сборка также запускаются в GitHub Actions (`.github/workflows/ci.yml`).

## Настройка

Переменные окружения описаны в `.env.example`. Лимиты и комиссии по активам задаются в `server/src/domain/assets.ts`:

| Валюта | Пополнение | Вывод | Комиссия вывода | В сутки | Выплата |
|---|---|---|---|---|---|
| ₽ RUB | 100 – 1 000 000 | 300 – 500 000 | 50 ₽ | 1 000 000 | USDT |
| $ USD | 2 – 10 000 | 5 – 5 000 | 0,5 $ | 10 000 | USDT |
| € EUR | 2 – 10 000 | 5 – 5 000 | 0,5 € | 10 000 | USDT |
| ¥ CNY | 15 – 70 000 | 40 – 35 000 | 4 ¥ | 70 000 | USDT |
| TON | 0,5 – 5 000 | 1 – 2 000 | 0,02 | 4 000 | TON |

Комиссия обмена и спред при выводе фиата в USDT задаются переменной `EXCHANGE_FEE_BPS` (100 = 1 %).

## API

Все запросы `/api/*` передают заголовок `Authorization: tma <initData>`, а все, кроме `/api/auth/*`, ещё и `x-wallet-session` после ввода кода.

| Метод | Путь | |
|---|---|---|
| GET | `/api/auth/state` | экран блокировки: профиль, задан ли код (без сессии) |
| POST | `/api/auth/setup`, `/api/auth/unlock` | создать код / войти по коду → сессия `x-wallet-session` |
| GET | `/api/me` | профиль, балансы, валюты, лимиты, курсы |
| POST | `/api/exchange/quote` | `{from, to, amount}` → зафиксированная котировка |
| POST | `/api/exchange` | `{quoteToken}` + `Idempotency-Key` |
| GET | `/api/history?cursor=` | история операций (keyset-пагинация) |
| POST | `/api/deposits` | `{asset, amount}` + `Idempotency-Key` → счёт |
| GET | `/api/deposits/:id` | статус пополнения |
| POST | `/api/withdrawals` | `{asset, amount, pin}` + `Idempotency-Key` |
| GET | `/api/withdrawals/:id` | статус вывода |
| POST | `/api/pin/change` | смена кода |
| POST | `/api/webhooks/cryptopay` | вебхук Crypto Pay (подпись) |
| GET | `/api/health` | проверка живости |

## Перед запуском в прод

- [ ] **Юридическая сторона.** Хранение и обмен рублей, долларов, евро и юаней для других людей во многих странах, в том числе в России, — лицензируемая деятельность (электронные деньги, обмен валют, KYC/AML). Перед запуском с реальными деньгами проконсультируйтесь с юристом
- [ ] Убедитесь, что `getExchangeRates` вашего приложения Crypto Pay отдаёт курсы для всех включённых валют

- [ ] `CRYPTOPAY_NETWORK=mainnet`, токен основного приложения, включены Transfers, на балансе приложения есть средства
- [ ] `BOT_MODE=webhook`, задан длинный случайный `TELEGRAM_WEBHOOK_SECRET`
- [ ] Домен указывает на сервер, `https://<домен>/api/health` отвечает `{"ok":true}`
- [ ] Резервные копии PostgreSQL
- [ ] Мониторинг логов с `withdrawal moved to manual review` и `paid invoice does not match deposit`: это ситуации для ручного разбора
- [ ] При нескольких репликах счётчики частоты запросов нужно перенести в Redis (`@fastify/rate-limit` поддерживает это из коробки). Воркеры к нескольким репликам уже готовы
